# Daily source refresh and release

Authorized by Robert October 11, 2026. This supersedes the Thursday-only DFS cadence. Run at 08:00 America/Chicago through the existing Bowser automation, which requires Codex and its local execution host to be available. Each run checks the public NFL statistics, DFS, and public waiver research independently. A failed feed keeps its last verified published data and cannot block a changed, independently verified feed. Yahoo ownership is separate: the connected browser refreshes its encrypted private snapshot; this job must never import Yahoo data.

1. Read current AGENTS.md, fetch `RBarbieri13/Bowser` main, and inspect the permanent Vercel deployment metadata. Work from the newest verified main in an isolated checkout; preserve all unrelated work and historical archives. Never reset a dirty checkout. Stop if a newer deployment cannot be reconciled with main.
2. Record source hashes and copy the current 2026 warehouse/report/raw inputs into an ignored backup directory. Record the immutable 2025 warehouse hash. Run `python3 scripts/import_nflverse_2026.py --refresh` with a 30-minute timeout and no dev server holding that checkout's warehouse. Run `python3 scripts/verify_warehouse_2026.py`. On failure restore the staged backup and stop publication of NFL statistics. Continue independent DFS and waiver checks against the last verified schedule. Do not hand-edit statistics. Compare actual source hashes (not import timestamps); restore the original tracked stats files if all source hashes are unchanged.
3. Run `python3 scripts/import_dfs_weekly.py` with a 15-minute timeout and verify with `python3 scripts/import_dfs_weekly.py --verify`. Publish new DFS data only with `publishable:true` and an offline PASS. When the source gate fails, preserve the last verified DFS snapshot and archive byte-for-byte and record the exact week, slate and reason. Do not weaken the schedule, salary, position coverage or projection checks. Keep locked historical captures immutable and retain separate official FLEX/CPT prices and explicit 1.5× Captain projections.
4. Each day determine the waiver week from the published 2026 NFL schedule and look for fresh public expert waiver rankings and FAAB advice for that week. Check the last published snapshot's actual week, capture and source dates. On new source evidence, prepare a JSON map of capture keys to verified public publisher URLs using `CAPTURE_HOSTS` in `scripts/import_waivers_current.py`. Run `python3 scripts/import_waivers_current.py --week <week> --html-dir <new-ignored-capture-folder> --urls <reviewed-urls.json>` to record source HTML, URL, UTC capture time, and SHA-256 and validate the snapshot. Existing reviewed captures can be replayed by omitting `--urls`. Run `python3 scripts/import_waivers_current.py --verify-all`. Require at least five genuine ranking publishers and five genuine FAAB publishers. Verify the exact week, numeric inputs, identities and source units. Preserve prior weeks and the Git history of revisions. If publishers have no material change, retain the capture timestamp. If publication or the coverage gate fails, retain the last verified waiver snapshot, record the missing week/sources, and continue with any other verified feed. Never publish private Yahoo data or the private briefing pack through this lane.
5. For changed verified data run `npm run check` and `npm run lint`, compare scheduled/completed/sourced coverage by week, and verify the 2025 hash is unchanged. Stop on red checks. Do not alter tests merely to advance a date or lower completeness thresholds; new schedule weeks can legitimately have byes or partial coverage. Correct genuine dated test assumptions only with preserved historical fixture checks and review.
6. Independent read-only review must pass. Commit only intended verified data/code; push a branch, create/attach a PR, verify GitHub checks and the Vercel candidate with `python3 scripts/verify_trend_release.py --vercel --url <candidate> --output <ignored-evidence>`. Merge that exact reviewed head to main only on PASS. Use existing GitHub/Vercel integration; do not create another project or change secrets.
7. Verify the permanent https://bowser-fantasy-football.vercel.app and https://fantasy-football-stats-preview.vercel.app aliases, source dates, latest complete week, current schedule-selected DFS week, salary/projection/value readbacks and historical captures. Read back the default and exact new Waivers week and compare source counts and prior-week actuals. Save only public/aggregate release evidence: commit, PR, deployment ID/URL, source counts, exact season/week/slates and verifier results. Distinguish missing upstream data from stale app data.
8. Each run is bounded to two hours. Stop after three repeated correction failures; no purchases, new credentials, unbounded retries, fabricated fields or privacy exceptions. Keep the last verified data for a failed feed, or the previous full release if a shared release gate fails. Notify only on a changed successful release, failure, or required action. Quiet on unchanged/non-actionable results. Record pass, unchanged or blocked separately for each feed even when there is no release. If all validated feeds are unchanged, stop without a commit or deployment.

The UI derives DFS Tuesday rollover from the published full NFL schedule. Player Database can show a partially imported statistics week once its first completed game has sourced data. Waivers opens the latest verified expert edition and uses the latest completed prior statistics week. If a provider is late, the app retains the actual latest complete week and reports missing slates/values rather than substituting older-week data. The browser Refresh all button reloads the most recent published snapshots; it cannot execute local importers on Vercel.
