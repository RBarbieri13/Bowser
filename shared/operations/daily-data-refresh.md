# Daily source refresh and release

Authorized by Robert October 11, 2026. This supersedes the Thursday-only DFS cadence. Run at 08:00 America/Chicago through the existing Bowser automation, which requires Codex and its local execution host to be available. Yahoo ownership is separate: the connected browser refreshes its encrypted private snapshot; this job must never import Yahoo data.

1. Read current AGENTS.md, fetch `RBarbieri13/Bowser` main, and inspect the permanent Vercel deployment metadata. Work from the newest verified main in an isolated checkout; preserve all unrelated work and historical archives. Never reset a dirty checkout. Stop if a newer deployment cannot be reconciled with main.
2. Record source hashes and copy the current 2026 warehouse/report/raw inputs into an ignored backup directory. Record the immutable 2025 warehouse hash. Run `python3 scripts/import_nflverse_2026.py --refresh` with a 30-minute timeout and no dev server holding that checkout's warehouse. Run `python3 scripts/verify_warehouse_2026.py`. On failure restore the staged backup and stop publication. Do not hand-edit statistics. Compare actual source hashes (not import timestamps); restore the original tracked stats files if all source hashes are unchanged.
3. Run `python3 scripts/import_dfs_weekly.py` with a 15-minute timeout. Require `publishable:true`; run `python3 scripts/import_dfs_weekly.py --verify`. Source absence or failed gates must not be bypassed. Keep locked historical captures immutable, exact Classic/Showdown FLEX/CPT prices and explicit 1.5× Captain projections. Never use historical averages as projections. The prior `changed:false` terminal rule now applies to the combined statistics/DFS result: if neither has changed, stop without commit/build/deploy/notification.
4. For changed verified data run `npm run check` and `npm run lint`, compare scheduled/completed/sourced coverage by week, and verify the 2025 hash is unchanged. Stop on red checks. Do not alter tests merely to advance a date or lower completeness thresholds; new schedule weeks can legitimately have byes or partial coverage. Correct genuine dated test assumptions only with preserved historical fixture checks and review.
5. Independent read-only review must pass. Commit only intended verified data/code; push a branch, create/attach a PR, verify GitHub checks and the Vercel candidate with `python3 scripts/verify_trend_release.py --vercel --url <candidate> --output <ignored-evidence>`. Merge that exact reviewed head to main only on PASS. Use existing GitHub/Vercel integration; do not create another project or change secrets.
6. Verify the permanent https://bowser-fantasy-football.vercel.app and https://fantasy-football-stats-preview.vercel.app aliases, source dates, latest complete week, current schedule-selected DFS week, salary/projection/value readbacks and historical captures. Save only public/aggregate release evidence: commit, PR, deployment ID/URL, source counts, exact season/week/slates and verifier results. Distinguish missing upstream data from stale app data.
7. Each run is bounded to two hours. Stop after three repeated correction failures; no purchases, new credentials, unbounded retries, fabricated fields or privacy exceptions. Keep the previous verified release on failure. Notify only on a changed successful release, failure, or required action. Quiet on unchanged/non-actionable results.

The UI derives Tuesday rollover from the published full NFL schedule and only advances statistics through complete imported weeks. If a provider is late, the app retains the actual latest complete week and reports missing slates/values rather than substituting older-week data. The browser Refresh all button reloads the most recent published snapshots; it cannot execute local importers on Vercel.
